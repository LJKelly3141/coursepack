# course-accessibility-review

Audits a course repository against WCAG 2.1 Level AA, classifies every finding
by how it gets fixed, and writes a prioritized remediation plan. Generic over
any course repo: nothing in `coursepack::audit_course()` or the package's audit
library is hardcoded to one course, one framework, or one path.

## Read this before every run

Re-read these first, every time, even if this skill has run before in this
session. The workspace boundary and the source-only rule below are
load-bearing and must not be inferred from the file tree:

1. `CLAUDE.md`. The declared workspace, and the render-allowlist and
   answer-key containment rules that make `docs/` public and everything else
   private.
2. The course's decision record, if it keeps them. Why this skill audits
   HTML output rather than reasoning over source, why it is served over HTTP
   rather than read as `file://`, and the handling paths for the surfaces
   below.

## What it audits, and what it does not

Three surfaces, three handling paths. Which pages exist under each surface
comes from `discover_target()`, not from a fixed list.

| Surface | Method | Fixes land in |
|---|---|---|
| Textbook rendered output | pa11y over served HTML | `.qmd`/`.Rmd` sources, and a stylesheet if the repo has none yet |
| Shell rendered output | pa11y over served HTML | `.qmd`/`.Rmd` sources, `style.css` |
| Cartridge `.imscc` | unzip to a temp dir; static audit of `wiki_content/`; the iframe and link-text rules over every announcement body; link-text quality over every `imswl_xmlv1p1` weblink; YouTube embed availability and captions | `modules.yml`, the announcement body file, or the coursepack cartridge builder |

**QTI (quiz zips) is NOT audited. There is no QTI code anywhere in this
skill.** Earlier versions of this file and of its decision record listed a fourth
"QTI, structural checks only" surface. No script has ever read a QTI zip,
and a listed-but-unimplemented surface reads as coverage the tool does not
have, so the row is gone rather than left in as an intention. Adding it is
real work, not a wiring change: nothing in the package opens `build/qti/`.

**Every fix lands in a source or template file. Never in `docs/`, never in a
built `.imscc`, never under `build/`.** All three are regenerated by the next
build, so an edit there is silently discarded the next time anyone runs
`make site` or `make coursepack`. If a finding cannot be traced to a real
source file that a person can open and edit, that is a bug in the finding,
not an invitation to patch the rendered copy.

Non-HTML media (images, PDFs) is inventoried, not audited: `inventory_media()`
lists what pa11y and the HTML-layer checks structurally cannot see, so nothing
goes missing by silent omission. The audit calls it once per repo and the
report carries a per-surface count table, with every path in the JSON.
Classifying a listed file as in scope, a working file, or
published-but-out-of-scope is a per-repo editorial call, not something the
inventory decides on its own. (It said all this for a day while nothing
called the function; wired up 2026-08-13.)

## Coverage is measured, and it is not the same number as the declaration

The report states three separate things, from three different code paths, and
they are only ever meaningful together:

- **Pages examined.** Accumulated inside the audit loops, one increment per
  page pa11y actually returned output for and per wiki page actually read.
- **Declared scope.** What `intended_surfaces()` said target discovery found
  to audit, computed independently of any loop.
- **Pages the tool could not read.** Reported unconditionally, including as
  an explicit zero, because a page pa11y failed on is a page the report says
  nothing about.

A measurement below its declaration prints `COVERAGE SHORTFALL` and names
both numbers. This exists because for one round both the count and the
surface list were built from one `intended_surfaces()` call, which made the
cross-check compare a value against itself: an entire audit loop could be
removed and the report still printed a full page count and read clean. Never
derive the measurement from the declaration.

**A cartridge surface's page count is the sum of wiki pages across every
`.imscc` found under that repo.** If a repo holds an export and its own
round-trip copy, as this project's `reference/` does, the same wiki page is
counted twice, and "12 pages examined" means 12 files read, not 12 distinct
pages. That is honest about what was read and misleading about what was
covered, so say which you mean whenever the number is quoted. **The report
now says it itself**, next to the number, naming how many `.imscc` files each
cartridge surface spans and warning about the double count when that is more
than one. A reader should never have to open this file to learn what a figure
in the report means.

**A re-audit on a bad connection lies in BOTH directions, and the dangerous
one is "fixed".** Caption and availability state are resolved against
YouTube's live watch page, and an unreachable YouTube resolves every video to
`undetermined`:

- **Looks like a regression.** Videos that had real captions now emit
  `undetermined` review rows, which diff as new findings.
- **Looks like a repair, which is worse.** A video previously reported as a
  dead embed also resolves to `undetermined`, so its broken-embed finding is
  simply absent this run and the diff reports it under `fixed`. Nothing was
  repaired; the tool just could not look. The `undetermined` row for that
  video says so in its own text, and it is the only thing standing next to
  the disappearance, so read the two together.

Check the network before believing either direction. Within a single run
this is at least self-consistent: a video is fetched once per run and every
page embedding it reports the same state.

## The WCAG 2.1 AA checklist

**Machine-verified by pa11y**, invoked with both of its bundled engines,
axe-core and HTML_CodeSniffer (`--runner htmlcs --runner axe`; pa11y's own
default is HTML_CodeSniffer alone, so this is not optional, see the gotchas
below): heading structure and landmarks, table headers, default link-text
quality, the presence of an `alt` attribute, `<html lang>`, page titles,
focus order, and contrast, with a computed ratio rather than a pass/fail
guess. Verified against a real full-course run, 2026-08-13: axe-core
corroborates most of what HTML_CodeSniffer already finds at the same
element and criterion, but also catches real defects HTML_CodeSniffer's own
checks miss entirely, including contrast failures on elements
HTML_CodeSniffer's contrast check does not flag, and a keyboard-focus check
(scrollable region focusability) HTML_CodeSniffer has no equivalent for at
all. axe-core reports its own rule name, not a WCAG technique code, so a
second lookup table (`AXE_CRITERION`, in the package's audit library) maps every
one of axe-core's rules that carries a real WCAG success-criterion tag to
that criterion, not just the handful a given course happens to trigger:
covering only what one course exercised was tried first and corrected the
same day, once a second, purely hypothetical course's `html-has-lang`
failure would have carried no criterion despite `AXE_CRITERION` already
existing. Every entry is verified directly against axe-core's own published
rule metadata, not memory. Rules confirmed to carry no WCAG tag at all
(`AXE_NO_WCAG_TAG`) are reported with no criterion, silently, since that is
a settled fact; an axe rule in neither table warns once per run rather than
being treated the same way, since that means this project's own mapping has
not been checked against whatever axe-core version is actually running.

**Covered by the three custom checks**, because pa11y genuinely cannot reach
these from rendered output alone:

1. **Filename-as-alt.** pa11y reports a *missing* `alt`. It does not report
   `alt="chart1.png"`, which is present, useless, and read aloud to a screen
   reader user verbatim.
2. **`fig-alt` missing at source.** pa11y reads the rendered page; the fix
   belongs in the source file. Sources are found recursively and include
   both `.qmd` and `.Rmd`, so a Quarto book with chapters in a subdirectory
   and a bookdown or R Markdown course are all scanned; build output,
   dependency caches, and backup directories are excluded by convention.
   **Directories the project declares as pass-through resources are excluded
   too**, read from the project's own config (`project: resources:`) and
   passed in by the driver as a REQUIRED argument, never a directory name
   written into the package. A source file inside one of those was copied,
   not rendered, so it is not a page this course publishes, which is the
   same reasoning `list_pages()` already applies to their HTML. Both source
   checks fail loudly if that argument is not supplied: a default would let a
   caller silently scan a course's working files and still look correct.
   Entries are matched as **globs** with Quarto's own semantics (`**` crosses
   path separators, `*` stays inside one segment, `?` is one character,
   everything else including `.` is a literal), because `resources:
   ["assets/**"]` is the common idiom and a literal-only match made it a
   silent no-op. An entry naming a path that does not exist warns that the
   exclusion it is meant to apply is not in force; an entry that simply
   matches no source file is normal and stays quiet.

   **`assessments/` is excluded unconditionally, as a containment rule.** The
   colour-only check copies raw source lines into the findings JSON and
   markdown, both committed, and answer-key material must not accumulate in
   artifacts by accident. It costs nothing: assessment sources are never
   rendered to HTML by design, so they have no accessibility surface and a
   finding against one could never be acted on. This is the one
   course-convention directory name in the checks, and a course that keeps
   answer keys elsewhere gets no protection from it.
   **A repo that yields no source files at all emits a loud finding saying
   so**, because a check that scanned nothing and a check that found nothing
   must never read the same. This check runs in one of two modes, and the
   report states which for every finding it produces:
   - **rendered**: a real PNG for that chunk was found under a Quarto-named
     `<stem>_files/figure-html/` directory and confirmed to lack `fig-alt`.
     Marked in the report as verified against a rendered image.
   - **source-heuristic**: nothing has been rendered for that file yet, so
     the check falls back to matching plotting calls in the source: R
     (`ggplot(`, `plot(`, `hist(`, and similar) and Python (`plt.`,
     `sns.`, and a pandas `.plot(` accessor), since both languages are
     first-class here. Marked in the report as **not verified**, because a
     fallback result must never be presented as if it were confirmed against
     real output. Render the file and re-audit before treating a
     source-heuristic finding as certain.
3. **Colour as the sole channel (1.4.1).** Flags plotting code using
   `aes(colour=` / `aes(fill=` with no second channel (`shape`, `linetype`,
   `alpha`, `size`, `label`). Never auto-fixed; every one routes to a human,
   because whether a given chart actually needs a second channel is a
   judgement about what the chart is for.

**There is no replacement-colour check, and this file claimed one for a
day.** `suggest_passing_colour()` exists in the package's audit library, is
correct, and is tested, but no audit path calls it and none can: computing a
passing colour needs a foreground/background PAIR, and neither engine gives
one through pa11y's JSON reporter. Verified against a real dual-runner
invocation, 2026-08-13: axe-core's contrast issue carries only its rule help
text and helpUrl, no colours and no ratio; HTML_CodeSniffer's carries the
measured ratio and its OWN already-computed recommendation ("change text
colour to #4455a8"), which the report already prints verbatim as the issue
text, but still no pair. The function stays for the day a runner exposes the
real colours; do not describe it as one of the custom checks until something
calls it.

The cartridge surface adds four more, all but the video checks static, and
none of them running pa11y against a wiki fragment (that would flag the
missing `<html lang>` and `<title>` Canvas itself supplies, which is noise,
not a finding):

- **Untitled iframes (4.1.2).** An `<iframe>` with no `title`, or an empty
  one, is announced to a screen reader only as "frame".
- **Weak or missing weblink text (2.4.4).** "Click here", a bare URL, or an
  empty `<title>` on an `imswl_xmlv1p1` weblink resource fails out of
  context, which is how a screen reader user scans a link list.
- **Unavailable embedded video.** Resolves each YouTube ID against the real
  watch page. A dead or private video is a more urgent defect than any
  caption gap it might be hiding behind, and is reported separately from a
  caption finding, never folded into one.
- **Captions (1.2.2).** The same resolution pass answers five states, and
  three of them are reported. `none` (a real, loading video with no caption
  track) and `auto-only` (every track is YouTube's own ASR track) are both
  Level A failures under 1.2.2, serious, and routed to class (c) human work:
  no generator edit captions a video. `undetermined` is a review row naming
  the video id, because "could not verify" has to appear in a compliance
  document rather than vanishing. `captions` and `unavailable` produce no
  caption finding, the second because there is no video to caption.
  Corrected 2026-08-13: all five states had been computed since the check
  was written and only `unavailable` was ever emitted, so a course with
  uncaptioned video and a fully captioned one produced identical evidence
  (none), while this file said captions were checked.

Every cartridge finding's surface names the course it came from, derived
from the repo the `.imscc` was found under, not a bare `"cartridge"`
constant: auditing more than one course in one invocation is supported, and
two different courses whose cartridges happen to share a conventionally
named page (a "syllabus.html" with a matching iframe target, for instance)
would otherwise produce findings that collapse into each other as an
"expected duplicate", silently losing one course's real finding. Corrected
the same day it was found.

Every finding carries a WCAG criterion and, where this project has a verified
level for it, the true conformance level (A, AA, or AAA), read from the
published WCAG 2.1 table rather than guessed. A criterion with no entry in
that table prints on its own, without a level attached, rather than a level
invented to fill the slot.

## The exact commands

```bash
make a11y                                                   # from the scaffold Makefile
Rscript -e 'coursepack::audit_course(c(".", "/path/to/textbook-repo"))'
Rscript -e 'testthat::test_local()'                         # in the package checkout
npx --yes pa11y@9.1.1 --standard WCAG2AA --reporter json --runner htmlcs --runner axe --include-warnings --include-notices <url>
```

## Alt text procedure

For every image or figure missing `alt`, open the rendered figure and write
what it actually shows: what is plotted, on what axes, and what the shape or
pattern is. Never write "a plot" or "a chart", generic filler that answers
nothing for a screen reader user. Describing a residual-versus-fitted plot,
or what a case study's regression output is showing, is a pedagogical
statement under the author's name, not markup, so it is drafted, never
authored without the author's own review.

Every draft alt-text string goes into the plan for the author to review and
is written into the `.qmd` as `fig-alt`. **No draft is ever marked done until
the author has read it.** A generated description that has not been reviewed
is a draft, however plausible it reads.

Do not add `fig-alt` to a chunk set to `eval: false`. A chunk that never
renders never produces an image, so there is nothing there for `fig-alt` to
describe.

## Colour-only findings are never auto-fixed

Every 1.4.1 colour-as-sole-channel finding is routed to a human, unconditionally,
as class (c). Whether a chart genuinely needs a second visual channel is a
judgement about the chart's purpose that no automated check can make safely,
and a wrong automatic edit here (adding a meaningless `linetype=` just to
silence the check) would be worse than leaving the finding open.

## Gotchas

- **pa11y exits nonzero when it finds issues. That is success, not failure.**
  `pa11y_raw()` never checks the exit code for this reason; it checks only
  whether the JSON output file exists and is non-empty. A wrapper that treats
  a nonzero exit as an error will misreport every audit that actually found
  something.
- **`--include-warnings` and `--include-notices` are mandatory.** Without
  them the JSON reporter silently returns only `type: "error"` issues.
  Measured on one real page: 242 errors by default, 699 once both flags were
  added, so the draft invocation without them was silently discarding 65
  percent of what pa11y actually found, including every contrast and
  structural warning. Never invoke a bare `pa11y` without these two flags.
- **pa11y's own default runner is HTML_CodeSniffer alone.** Passing no
  `--runner` flag does not run "both bundled engines"; it runs one. This
  project's own decision record assumed otherwise for one full working day
  (inferred from axe-core appearing in pa11y's dependency list, never
  checked against which runner actually executes) before a real invocation
  was inspected and found `runner: "htmlcs"` on 100% of a real page's
  issues, zero `"axe"`. `--runner` is repeatable
  (`--runner htmlcs --runner axe`), not comma-joined, per `pa11y --help`.
  Confirming the flag was accepted is not enough; confirm the `runner`
  field in real returned issues actually shows both values, or the flag may
  have been silently ignored. axe-core's own rule names carry no WCAG
  criterion number the way HTML_CodeSniffer's technique codes do, so
  enabling axe also requires the `AXE_CRITERION` lookup in the package's audit
  library to classify what it finds; without it, every
  axe-sourced finding gets no criterion and cannot be swept into a class
  (a) shared-edit group even when it genuinely belongs in one.
- **The first run downloads a Chromium.** Budget real time for it on a cold
  machine. `--help` exiting cleanly is not proof the browser will launch;
  the first real audit call is the actual test. If a pinned-version
  invocation fails with a `dlopen` error naming a missing framework, that is
  a corrupted Chrome-for-Testing cache, not a network problem: reinstall the
  browser with `@puppeteer/browsers install`, always passing `--path`, so the
  browser lands in the Puppeteer cache and not the current directory.
- **`file://` auditing is invalid.** Chrome gives every `file://` document a
  unique opaque origin, so a headless audit of local files sees a different
  document than a student does, and any framed content fails to load at all.
  Everything is served over `python3 -m http.server`, audited, then torn
  down; there is no supported path that skips this.
- **Framework files regenerate on build.** `docs/`, `.quarto/`, and every
  Quarto-managed `*_files/` directory are overwritten on the next render. A
  fix applied there disappears silently at the next `make site`. The fix
  always lands in the `.qmd`, the stylesheet, or the generator script that
  produced the output, never in the generated file itself.
- **Theme variants need separate contrast checks.** A stylesheet with a light
  and a dark variant, or a Quarto theme list with more than one base, can
  pass contrast in one variant and fail it in another. Auditing only the
  variant that happens to render by default can miss a real failure in the
  other.
- **A surface identity is a directory basename, and the diff baseline is
  therefore NOT portable.** `repo_surface_base()` is
  `basename(normalizePath(repo))`, and the surface is hashed into every
  finding id, so auditing the same course from a different path (a fresh
  clone, a git worktree, a renamed directory) produces a completely disjoint
  id set: the next re-audit reports 100 percent fixed and 100 percent new,
  and the diff, which is the whole reason the JSON exists, silently becomes
  meaningless. Keep a course's audits anchored to one path, or re-baseline
  deliberately. Two repos that DO share a basename are the other half of the
  same fact and are no longer silent: the run halts rather than merging two
  courses into one surface. A stable per-repo identity (a git remote, a
  declared id in the repo's own config) would fix the portability half and
  is not a rename, and is recorded in the package NEWS as an open design
  question.
- **A generated finding names the check's real target, not a guess.**
  Cartridge findings arrive with `fix_target` already set by
  `audit_cartridge()` to `modules.yml` or the coursepack cartridge builder,
  because the wiki fragment inside the `.imscc` is generated and editing the
  zip directly is pointless. An announcement body is the exception: it is
  authored, one HTML file per announcement, so its findings name that file.

## What requires a human

- **Every colour-only (1.4.1) finding.** See above; never auto-fixed.
- **Every caption (1.2.2) finding.** Captioning is content work, one video at
  a time. A caption finding names the generator as its fix target because
  that is where the embed URL is authored, but it is class (c): no single
  edit there produces captions.
- **Caption verification when the video check returns `undetermined`.** The
  check reads YouTube's own undocumented watch-page payload and refuses to
  guess when the page it fetched cannot be confirmed to be a real player
  response, rather than a consent screen or a bot-check interstitial.
  `undetermined` means exactly that: go look at the video. It is emitted as
  a review-severity row rather than left silent.
**Do not put a compliance date in anything.** Settled 2026-08-13: these
courses are built compliant, not built toward a deadline. The remediation
plan is ordered by leverage and by student impact, which is the right
ordering whether or not a deadline exists. Do not research the date, do not
cite one in a report, and do not add dated milestones. If a future reader
wonders why the plan carries no dates, this is why.
