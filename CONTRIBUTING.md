# Contributing to coursepack

## Whether contributions are taken at all

This is an open question, not a policy. The package was extracted from a working
course toolchain and put into public view so that the courses built with it can
depend on something installable; whether pull requests, issues and outside
patches are accepted, and under what terms, has not been decided. Nothing here
should be read as an invitation or as a refusal. Until the maintainer decides and
this section is rewritten, the safe assumption is that an unsolicited pull
request may sit unanswered. Opening an issue to ask first costs nothing.

Everything below applies to any change to this package, including the
maintainer's own. It is the shape the code has to keep.

## The arrival rule

Every exported entry point takes the course project root, `proj`, as its first
argument, and reads and writes nothing outside it.

- No absolute paths anywhere in `R/`, `inst/` or `tests/`. Not in code, not in a
  default, not in a comment.
- No `Sys.getenv()` in `R/`. A setting that has a default belongs in an argument,
  because `make` exports an unset variable as an empty string and
  `Sys.getenv(name, default)` does not fall back on empty, so a name exported by
  accident silently disables the thing it was meant to configure. The two
  environment variables this project does use are read in the test suite only,
  and they gate tests rather than configure behaviour.
- Course facts live in that course's YAML: the code, the title, the site URL, the
  timezone, the term window, the Canvas settings, the due time. Not in package
  code, not in a skill, not in a template as anything but a `{{placeholder}}`.
- A function that reaches outside the `proj` it was handed has broken the rule.
  That is a defect on its own terms, whatever it was trying to do.

## The separation rule

Courses are separate and stay separate. They share build tools and nothing else.
One installed copy of this package serves any number of courses without any of
them being able to see another, and that is a property of the code, not a
convention anyone is expected to keep by hand. A default that points at one
course, a search path that walks upward out of `proj`, or a constant naming one
institution's Canvas breaks it.

## Course content never enters this repository

No course name, course number, institution, person, repository path or course
prose belongs in `R/`, `inst/`, `tests/`, `man/` or the shipped documents. The
test fixtures are an invented course, `ABCD 101`, with hosts under
`example.invalid`, and new fixtures are invented the same way.

`tools/scrub.sh` is the audit. Run it from the package root before proposing
anything:

```
tools/scrub.sh
```

It greps the shipped tree for course residue, for this package's own repository
address outside the three files allowed to carry it, for `Sys.getenv()` in `R/`,
for absolute paths, for em-dashes in shipped text, and for token shapes anywhere
in the git history. It prints `scrub: clean` and exits zero, or it prints every
hit and exits non-zero. There is no allowlist to add yourself to: the allowed set
is two entries and both are load-bearing. `tests/testthat/test-scrub.R` runs the
same script from the suite, and skips only where the script is absent, which is
inside a built tarball.

## The byte gate

`tests/testthat/fixtures/minimal-course-expected-tree.txt` is a hash of every
file the builder stages for the fixture course. Any change to any generated byte
fails the suite.

**The gate is never regenerated to make a failing test pass.** A regeneration is
a deliberate output change. It goes in its own commit, whose message says the
cartridge was supposed to change and lists which staged files changed and why. If
you cannot write that sentence about your own change, the change is not finished.

The same discipline applies to the two other things that hold output still: the
three answer-key guards (truncation at the answer-key heading, the canary stop,
the pre-zip byte scan) stay independent, and none is removed because the other
two would have caught it. And every check reads what ships, meaning the staged
tree, the zip or the export, never the R object that wrote it.

## Running the tests

The whole suite, which is what a change has to pass:

```
Rscript -e 'testthat::test_local()'
```

Missing system tools produce skips, never failures. The suite uses `zip`,
`pandoc`, `python3`, `quarto`, `npx` and the `exams` package, and skips through
`tests/testthat/helper-skips.R` when one is absent. A skip for a missing tool is
expected; a failure is not, and neither is a skip for anything else.

Two sections are opt-in because of what they cost:

```
COURSEPACK_PA11Y_TESTS=1 Rscript -e 'testthat::test_local(filter = "a11y")'
COURSEPACK_NETWORK_TESTS=1 Rscript -e 'testthat::test_local(filter = "a11y")'
```

`COURSEPACK_PA11Y_TESTS` runs the accessibility audit end to end against a
fixture page carrying planted defects. It needs `npx`, `python3` and a Chrome or
Chromium binary, and the first run downloads a Chromium build, which is why it is
off by default. `COURSEPACK_NETWORK_TESTS` turns on the two sections that fetch
video caption state over the network. Neither is needed for a normal run, and
both should pass before a change to the audit is proposed.

The parity tests are the other conditional pair. They run the Python builder this
package replaces over the same fixture and compare the two outputs, which is what
proves the port did not quietly change anything. They need `python3` and the
snapshots under `project/`, they locate a snapshot by a file it must contain
rather than by its directory name, and they skip where either is absent, which is
the case inside a built tarball.

The full check, run from a scratch directory so the tarball never lands in the
tree:

```
R CMD build --no-build-vignettes .
R CMD check --no-manual coursepack_*.tar.gz
```

It stays at 0 errors and 0 warnings.

## Failing loudly

A missing body, a missing announcement body, an unknown `post:` form, a published
`todo:`, a collapsed quiz identifier, an unknown `canvas:` key, a `source_ref`
that names nothing in the source: all of these stop the build. None of them warns
and continues, and none of them is skipped. The reason is that the failure mode
on the other side is silent: Canvas discards malformed content without saying so
and reports a successful import, so anything this package lets through it will
never hear about again. When you add a case, add its refusal and its message
before you add its happy path.

## Writing

No em-dashes in anything shipped or student-facing: `R/`, `inst/`, `README.md`,
`NEWS.md`, `CONTRIBUTING.md`, the templates, the skills, generated HTML. Rework
the sentence with a comma, a conjunction or a full stop rather than swapping the
character. The scrub greps for it.

Comments and messages explain why, not what. An error message names the file, the
key and what to do about it, because the person reading it is holding a course
that will not build and a deadline.

## Version discipline

A change in behaviour bumps the fourth component of `Version:` in `DESCRIPTION`
and adds a `NEWS.md` line saying what changed and whether the cartridge output
changed with it. Every exported entry point prints `coursepack <version>` in its
closing summary, so the version in a build log is the version that wrote it.
