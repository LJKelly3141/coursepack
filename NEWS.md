## Known limitations

Standing as of 1.0.0. Each is a thing this package does not do, or does in a
way worth knowing before it surprises somebody.

* `LEAK_CANARY` and the answer-key heading pattern are package constants rather than per-course settings, so a course cannot choose the canary string planted in its assessment sources or the heading the body builders truncate at.
* A `description:` assignment is written with the one `assignment_settings.xml` template every assignment gets, so the extra elements the Python generator emitted on a generated assignment are deliberately not written, and that divergence is declared rather than closed.
* `extract_manifest()` does not extract announcements, grading standards, the late policy or LTI links; it counts them in its closing summary and writes none of them, so a course rebuilt from an export loses them until they are authored again.
* An accessibility surface's identity is `basename(normalizePath(repo))`, so a findings baseline does not follow a repository into a fresh clone, a worktree or a renamed directory, and the diff against the previous run starts over there.
* Exam pools are not ported. They were retired upstream on 2026-09-04, and `convert_python_manifests()` prints an `exam_pools:` block as a note rather than writing anything from it.
* The local `{site}` base is a reading of an ambiguous requirement rather than a verified one: in local preview mode the course's own `docs/` is served at `/site` and every `{site}` token is rewritten to point there. It is recorded here because it was decided, not confirmed.
* An unknown module item content type in an export, a discussion, an attachment or an LTI item, stops `extract_manifest()` rather than being counted, and the "not extracted" counts cover resources only.
* A course extracted from an export carries `term: timezone: UTC` and `carry: repair_html: false`, which is what makes the first rebuild reproduce the export; both belong to the carried `due:` instants above them and have to be changed together with those dates or every deadline moves.
* `answer_ids()` hashes the way the Python generator did but `gid()` does not, so a course leaving that builder has to pin `resource_id:` on its carried definitions, which `convert_python_manifests()` writes, or the first import creates a second copy of the course instead of updating the one already there.
* Explicit `resource_id:`, `item_id:` and `module_id:` overrides are not checked for collisions with each other or with the derived identifiers, so a duplicated override reaches the manifest and Canvas reports it at import rather than the build stopping first.
* A carried assignment's HTML `<title>` is the bare definition title while a generated body uses `Assignment: <title>`, and a carried quiz's `assessment_qti.xml` keeps the source course's title in its `<assessment>` attribute; Canvas displays the title from the meta file, so both are cosmetic.
* The carried-HTML repair matches tables non-greedily, as the generator it was ported from did, so a nested table can be mis-indexed (every `<th>` still gets a scope); a `<th>` that already carries a wrong scope is left alone rather than corrected; and `repair_html` is a per-course switch, all or nothing.
* A generated announcement body's leading `<h2>` is left unescaped on purpose so it matches the declared title the builder compares it against, and apostrophes are not escaped either (they are legal HTML), so a body carrying an apostrophe differs from the bytes the Python generator wrote for it.
* Nothing pins a printed paper form against the Canvas quiz item for item beyond the `bank_groups()` both of them call, a `homework:` form carries absolute image URLs that quarto fetches at render time so an unreachable host leaves a gap in the document, and the render test runs under `R CMD check` whenever quarto is on the PATH.
* `init_course(from_export =)` rewrites the extracted manifests through `yaml::write_yaml()`, so the comments the extractor wrote do not survive it; the one about carried UTC dates is printed instead of enforced, and `git = TRUE` and the interactive prompts are covered by reading rather than by a test.
* When announcements fall back to `course.yml`'s `term:`, a malformed date is still reported as `announcements.yml: term first_day`; only the missing-key stop names both files.
* The scaffold Makefile's `mockup` and `site` recipes are not exercised by the test suite.
* The course tile's byte-reproducibility test depends on a font present on the authoring machine; one intermittent failure was seen under `R CMD check` before this plan began and has not recurred since.

# coursepack 0.4.0

Carry, extract, generate and print are in the package: the capabilities of the second course's Python builder arrive in R against synthetic fixtures, and build, extract, build reproduces the staging tree.

* `print_assessment()`: a fixed draw under a seed, as Word and PDF, with a key. A bank quiz in Canvas is a draw nobody ever holds whole, and a make-up sitting, a proctored room and an accommodation each need one form on paper. `print_assessment(proj, id, seed, out_dir =, formats =, render =)` writes `<id>-seed<seed>.qmd` and, for a quiz, `<id>-seed<seed>-key.qmd` beside it. The draw is `set.seed(seed)` and then one sample without replacement from each group `bank_groups()` returns, in group order, so the same seed prints the same paper and a different one prints another; nothing written carries a timestamp, because `date: today` in the front matter is a Quarto keyword resolved at render, so two runs of one seed are byte-identical files. Stems are HTML in a bank and go through pandoc to Markdown with tables written as pipe tables, a figure copied beside the document and referenced by its bare filename with the bank's alt text, and the options listed `A.` to `D.` in bank order; the key is a table of number, chapter, section, bank id and answer as printed, with the seed and the package version above it. An assignment declaring `description:` or `homework:` prints its body the same way and has no key. A `qti:` quiz, a `quiz_file:` assignment and any carried `source_ref:` definition are refused, because their student-facing text lives where this package does not read and a form built from the part it can see would be missing the questions. With `render = TRUE` and quarto on the PATH each format is rendered beside the document, and without quarto the documents are written and where they are is printed. No cartridge output changed: nothing here is staged.
* A `link:` item's `url:` now takes the same `{site}` and `{textbook}` tokens an iframe page's `src` does; before this the token reached `module_meta.xml` and the weblink resource literally. The cartridge was supposed to change: those two staged files.
* `convert_python_manifests(course_py, modules_py, out_dir, bank_dir =)` writes this package's schema from the manifest schema of the toolchain it replaces. It is a migration a course runs once, by hand, and what it is for is identifiers: `gid_py()` reproduces the identifier convention that toolchain used, which joins a key's parts with `::` where this package's `gid()` joins them with nothing, and every module, item and resource identifier is written into the converted files so the first import after the migration updates the Canvas objects that are already there instead of creating a second copy of the course beside them. A resource identifier the old file did not name is derived by the old rule rather than left out, because that is the identifier its own builder used. `course_code:` becomes both `code:` and `canvas: course_code:`; `urls:`, `term:` and `due_time:` travel unchanged; `textbook_docs: none` is written; the `canvas:` block is filtered through `CANVAS_SETTINGS_KEYS` and an unknown key stops. The title-keyed `due_dates:` map dissolves into a `due:` on each definition, and a key naming no definition stops rather than being ignored. A wiki page with a `url:` becomes an `iframe:` page and one marked `carry_through:` a `source_ref:` page; a quiz or assignment with a `generate:` block becomes a `bank:` quiz or a `description:` assignment, and one without becomes `source_ref:`. A generated quiz that named no group is given `Module Quizzes`, the default the old generator applied without writing down; a generated assignment naming none stops, as it did there. Nothing is dropped in silence: a `generate:` key the converter does not read, an item type it cannot write, a page with neither a `url:` nor `carry_through:`, and a bank directory the block names but the caller did not, all stop, and the two things with no home in this schema, `exam_pools:` and `canvas: course_image:`, are printed as notes. Positions are not written, because here a module's and an item's position is its place in the file; where the two disagree the converter prints `positions renumbered: <old> -> <new>`, and positions that do not strictly increase, or two definitions of one kind claiming one title, stop before anything is written. The old file's leading comment block is copied verbatim to the top of the new `modules.yml`. No cartridge output changed.
* `announcements_from_schedule(proj, schedule =, out_dir =, release_time =, calendar_url =)` turns a `schedule.yml` into one weekly announcement: an HTML body per week under `out_dir` opening with its own `<h2>`, and an `announcements.yml` declaring them, which is the contract `build_cartridge()` already reads. A week carries `monday:`, `module:`, an optional `label:` and `notes:`, and any of `tuesday:` to `sunday:` as a class day with `class:` or `holiday:` and optional `assigned:` and `prepare:`; the body writes one `<h3>` block per declared day in weekday order and closes with what is due by Sunday. The due items are the manifest's own assignments and quizzes that declare a `due:`, not a title-keyed map maintained beside the manifest, so an announcement cannot disagree with the cartridge it announces; an item due Monday to Thursday is listed under its own day, Friday to Sunday collect into the closing list, and an item due on a day the schedule does not declare still gets a heading rather than being dropped. A `monday:` that is not a Monday, a week with no `module:`, a class day that is not a mapping, and two weeks sharing a Monday all stop. An existing `announcements.yml` is never overwritten: the declaration goes to `announcements.generated.yml` and the function says so.
